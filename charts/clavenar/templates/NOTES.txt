{{- if .Values.services.console.operatorMtls.enabled }}

Console operator mTLS is enabled on port 8085. TLS terminates in the
console process and a client must present a CA-valid certificate whose
fingerprint + SPIFFE URI exactly match an active operators.json entry:

  kubectl -n {{ .Release.Namespace }} port-forward svc/{{ .Release.Name }}-console 8085:8085

Keep the operator CA private key and operator leaf private keys outside
the cluster. Forwarded client-certificate or role headers are ignored.
{{- if .Values.services.console.demo.enabled }}

The separate curated demo listener is enabled on plain HTTP port 9085:

  kubectl -n {{ .Release.Namespace }} port-forward svc/{{ .Release.Name }}-console 9085:9085
{{- end }}
{{- else }}

Console is in the safe demo-only posture on plain HTTP port 8085. A
valid signed demo cookie is prefix-scoped and never grants an operator
session or Admin authority:

  kubectl -n {{ .Release.Namespace }} port-forward svc/{{ .Release.Name }}-console 8085:8085
{{- end }}

Console diagnostics are container-only on plain HTTP port 9185. Kubelet
and Prometheus use this listener; inspect it locally through the
Deployment, not the application Service:

  kubectl -n {{ .Release.Namespace }} port-forward deploy/{{ .Release.Name }}-console 9185:9185
  curl localhost:9185/health
  curl localhost:9185/readyz

Health/readiness:

  curl localhost:8081/health   # brain
  curl localhost:8081/readyz
  curl localhost:8082/readyz   # policy-engine
  curl localhost:8083/readyz   # ledger
  curl localhost:8084/readyz   # hil
  curl localhost:8086/readyz   # identity
  curl localhost:8087/health   # deep-review
  curl localhost:8088/health   # assurance

Proxy serves /mcp on its mTLS port (8443). /health, /readyz, and
/metrics are on a non-mTLS health listener (8080 by default,
container-port only — not published by the Service). Kubelet probes
target 8080. To exercise the mTLS path locally, point a client with
valid certs at https://localhost:8443/ per clavenar-proxy/README.md.

{{- if and (not .Values.tlsBundle.secretName) (not .Values.tlsBundle.autoMint) }}

WARNING: tlsBundle.secretName is empty.

The proxy panics at boot without /certs mounted (see clavenar-proxy
recurring-gotchas in CLAUDE.md). Three ways forward:

  1. Auto-mint inside the cluster (quickstart path):

       helm upgrade {{ .Release.Name }} . --reuse-values \
         --set tlsBundle.autoMint=true \
         --set tlsBundle.secretName=clavenar-certs

  2. Mint locally and project as a Secret:

       clavenar-proxy/scripts/gen_certs.sh --env prod
       kubectl -n {{ .Release.Namespace }} create secret generic clavenar-certs \
         --from-file=clavenar-proxy/certs/
       helm upgrade {{ .Release.Name }} . --reuse-values \
         --set tlsBundle.secretName=clavenar-certs

  3. Reuse an existing bundle Secret your PKI already publishes.
{{- end }}

{{- if and .Values.tlsBundle.autoMint .Values.tlsBundle.secretName }}

Auto-mint mode: a pre-install Job populates the Secret
`{{ .Release.Namespace }}/{{ .Values.tlsBundle.secretName }}` with a
self-signed CA + per-service workload certs. Use this for evaluation
clusters only — production deployments should ship a bundle from a
managed PKI (set `tlsBundle.autoMint=false` and provide
`tlsBundle.secretName` from an existing Secret).
{{- end }}

{{- if .Values.nats.bundled.enabled }}

Bundled NATS: the upstream nats-io/nats subchart is installed as
`{{ .Release.Name }}-nats`. JetStream persistence (when enabled in
your values) lands on a PVC. `helm.url` is auto-overridden to
`nats://{{ .Release.Name }}-nats:4222` for in-stack reach.
{{- end }}

{{- if .Values.vault.bundled.enabled }}

Bundled Vault (DEV MODE): the upstream hashicorp/vault subchart is
installed at `{{ .Release.Name }}-vault` with a known root token
({{ .Values.vault.bundled.devToken }}) and no persistence. A
post-install hook Job enables the transit engine and creates the
`{{ .Values.vault.bundled.transit.keyName }}` key. Dev-mode Vault
loses state on pod restart; the hook re-runs on every chart upgrade
and re-provisions the key. Do not use this configuration for
production — flip `vault.bundled.enabled=false` and supply your own
Vault via `vault.addr` + `vault.tokenSecretName`.
{{- end }}

{{- if not .Values.networkPolicy.enabled }}

treats k8s NetworkPolicy as the deployment perimeter. Enable when
your CNI supports it:

    --set networkPolicy.enabled=true
{{- end }}

default-on NetworkPolicy + replica-aware PDBs. See
